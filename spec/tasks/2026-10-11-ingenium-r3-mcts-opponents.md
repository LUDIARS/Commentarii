# Ingenium R3: MCTS・相手モデル 5 方式・hybrid・方式評価・敵 AI 再利用

設計正本: `spec/plan/2026-10-11-ingenium-integrated-design.md`。詳細は Fable 案 `spec/plan/2026-10-11-autoplayer-paradigms-fable.md` §3.6 (MCTS 提案者)、§3.10 (相手のモデル)、§7.3 (R3 の受入)。Astra 案 `spec/plan/2026-10-11-autoplayer-paradigms-astra.md` §4.2 (contextual bandit の制約)、§4.7 (相手の 5 方式モデルと MCTS)、§7.5 (敵再利用)。

前提: R2 がマージ済み。作業は Ingenium リポ。

## 成果物 (Ingenium)

1. **MCTS 提案者**: UCT、相手手番 (相手の挙動モデルが見えれば `policy`、見えないリアルタイムは学習モデル (事前は一様) の `policy`、見えないターン制は `adversarial`)、根の 1 手を返す (receding horizon)、論理予算 (反復数)、乱数は `deriveSeed(seed, "mcts:<tick>")`。木を長い BT に変換しない。任意: ターン制・決定的・2 人に深さ制限 minimax を同じ Planner 契約で。
2. **相手モデルの解釈器 5 方式**: R1 の fsm / scripted に加え、bt / utility / goap / mcts。相手視点のビューで私有情報に触れない。挙動モデルが masked なら観測からの遷移頻度で学習モデルを作る (`observations/opponents/`)。
3. **適格性判定と方式選択の完成**: Astra 案 §4.2 の優先表 (危険・計画の継続・不適格・GOAP 適格・MCTS 適格・フォールバック) を、R2 の予算表と合わせて選択器にする。GOAP と MCTS の両方が適格なときの計算配分。
4. **方式評価**: (a) bench で単方式・組合せ・選択器なしの対照を回し、局面署名ごとの方式別成績を集計する **オフライン補正** (予算表の変更は Commentarii の承認経路で人がレビュー)。(b) 制約付き **オンライン補正** (contextual bandit: 適格・境界・リスク制約を通った方式だけが腕、報酬は目標 episode 単位、版別に統計を分離、run 間更新を既定、run 内更新は更新列もリプレイ) を実装するが **既定は無効**。
5. **hybrid 構え**: 自分の計画と定石を同じ調停者で比べる。定石の効率書き換え (§8.2) の対照実験に使う。
6. **敵 AI 再利用**: 同じエンジンを敵・NPC の脳として動かす。self の差し替えだけで完了にせず、相手視点のビューとペルソナ (反応遅延・認知予算) の適用位置を明示。Bestia の 5 体の敵 AI を sim で置き換え、既存の固定 BT と同等以上を示す。
7. bench に方式別の寄与 (単方式 / 組合せ / 選択器) を出す。

## 受入条件

- `npm install --include=dev && npm run typecheck && npm test` が通る。
- 既知解のある小問題で方式ごとの単体テスト (MCTS: 三目並べ級で最善手、相手モデル 5 方式: 既知の挙動の予測一致)。
- 局面ごとに想定の方式が選ばれる (適格性の表に沿ったテスト)。
- 選択器ありが、単方式・選択器なしの対照より良い (bench で示す。良くない局面は記録して報告)。
- 敵視点で私有情報に触れない (テスト)。Bestia の敵 AI 置き換えで固定 BT と同等以上 (sim の bench)。
- オンライン補正の既定が無効であること、有効にしたときもリプレイで判断が再現することのテスト。
- 同じ seed で判断が再現する。
- PR 説明に: 変更した境界 / 復旧方法 / 実施した検証 / 未実施。

## 作業の進め方

- 作業場所は親が渡した worktree とブランチ。`main` を直接編集しない。Commentarii の内部パスを import しない。
- ビルドとテストはフォアグラウンドで待つ。サービスは起動しない。
- 完了 = Revisor local PR 提出 → **PR 番号と検証結果を報告してから** 終了指示を待つ。マージはしない。
